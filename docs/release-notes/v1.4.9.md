## 🐛 1.4.9：连接服务器后，命令历史不再被污染

- **按 ↑ 翻历史时不再看到一堆乱码命令**：此前 Ottr 为启用错误诊断与历史检索，
  会在连接后自动向远端 shell 下发一段集成配置。这些配置行被记进了服务器端的
  命令历史，按上方向键就会翻到几百字符的乱码。
  - **bash**：这些行现在完全不会留在历史里。
  - **zsh**：历史里只剩一条很短的记录。
  - **sh / ash（部分 NAS 与精简系统）**：钩子改为放进临时文件，历史里只留一条
    固定的短记录，并且文件用完即删。
- **不再出现 `stty: command not found`**：没有 `stty` 命令的精简系统（常见于 NAS）
  连接后不再刷这条报错。
- 注入过程本身对使用无影响：错误诊断、`⌘R` 历史检索、`⌘J` 目录锚点的行为不变。

已经存在的历史文件不会自动清理（那属于你的数据）；升级后新开的会话不再产生新的
注入残留，旧的可以自行在历史文件里删掉。

## 📦 平台提示

- macOS：本版本未使用 Apple 开发者签名。首次打开如提示「已损坏，无法打开」，在终端执行 `xattr -cr /Applications/Ottr.app`；
  连接局域网主机如提示 No route to host 或要求本地网络授权，见 README「macOS 提示已损坏或连不上局域网主机」一节。
- Windows：安装时如遇 SmartScreen 拦截，点「更多信息 → 仍要运行」；便携版
  （zip 解压即用）不提供应用内自动更新，升级请下载新版 zip 解压覆盖。
- Linux：AppImage 需 `chmod +x` 后运行；deb/rpm 按发行版安装。
