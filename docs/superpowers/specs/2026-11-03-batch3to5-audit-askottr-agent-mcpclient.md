## 1. 批次三：审计整改

三路并行审计（安全 / 功能健壮性 + 跨平台 / UI 与八语言）后，按「高危必修、阻断项必修、
其余排期」的口径整改。**审计结论没有一条被当作「以后再说」——除下面显式列出的遗留项。**

### 1.1 安全（1 条中危必修）

| 项 | 缺陷 | 修法 |
|---|---|---|
| 交互式认证 fail-open | 超时/取消时回**等长空串** → 条数校验通过 → **空密码被发给服务端**；服务端若允许空口令（`PermitEmptyPasswords`、PAM `nullok`）就会在用户完全没作答的情况下认证成功 | 空答案在客户端侧直接判 `AuthRejected`，**一个响应都不发**（`auth.rs` 加 `answers.is_empty()` 早退） |
| 脱敏覆盖面 | 规则集只认英文关键词 → 中文口令写法、`PGPASSWORD=`、URL userinfo、数字/十六进制 IP、PEM 私钥块、Bearer 令牌、shadow 哈希**全部原样出网**；且本批新增的注入源恰恰是用户手写的中文主机备注 | 规则集扩到 11 条（含中文关键词 + 全角冒号 + `password is X`）；**根因**：`i` 标志让 `(?<![a-z0-9])` 把大写前缀也挡住（`PGPASSWORD` 漏网）→ 去掉前置断言（误伤方向是多脱敏） |
| HTTP 能力门 | `http://*:*/*` 放行**任意主机的明文 http**；插件侧请求由 Rust 发出、**不受 CORS 约束** → webview 内任意脚本可读内网管理口与云厂商元数据 | 收窄为 `https://*:*/*` + 本机 http（localhost / 127.0.0.1）+ **显式 deny** 元数据地址与常见本地敏感端口；设置页保存前拦截**非本机明文 http** 端点 |
| 私钥落盘 | key 凭据写 OS temp 目录的 0600 文件 → Windows 无 0600 等价物（继承目录 ACL）、文件名可预测、任何提前返回都留残留 | **私钥全程在内存**（`AuthMethod::Key { source: KeySource::Pem }`），三个问题一并消失 |
| 机密面 | `TotpSecret` 派生 `Debug` → 种子字节数组进日志；验证码经 `app.emit` 全窗广播 | 手写 `Debug`（只输出存在标记）；事件改 `emit_to("main")` |

### 1.2 功能健壮性（必修）

* **私钥不落盘**（见上）、**key_deploy 限时 30s → 75s**（旧值小于 TOFU 问询窗口，
  用户的选择会作废且留下死槽位）、**8KB 输出尾截断不切碎多字节字符**（此前会切出
  U+FFFD）、**AI 空回答判失败**（端点回 HTML 时此前是「成功但一片空白」）、
  **断流的半截回答不入历史**、**并发交互式认证问询改队列**（原先单槽，后来者覆盖前者，
  前者的超时真因丢失）、**问询归属按 connect 序号**（原先靠数组顺序，同主机多会话会归错）、
  **对话历史封顶**（8 轮 + 16KB；原先每轮全量重发，token 平方增长）、
  **TOTP 位数/步长可配**（写死 6 位/30 秒 → Steam 5 位、8 位服务、60 秒步长的
  自建服务自动填码**恒错**）、**known_hosts 导入加固**（路径约束/条目上限/O(n) 归组/
  不占异步运行时线程）、**迁移夹具失真修复**、**`command_contract` 守卫自身失效修复**
  （扫描器把 JS 注释当调用点 → 误报淹没真问题）。

### 1.3 UI 与八语言（必修）

面板宽度上限、markdown 宽表滚动与多余空行、弹窗槽归属、追问框改 `<textarea>`
（并处理中文 IME 组字时的 Enter）、孤儿键清理、四语术语修正、**对比度按实算值重校**
（此前加的半透明底色 chip 反而把亮色主题拖到 4.39:1 → 撤掉，改用 tokens 已校准的
纯 danger 文字色）、**两个异步结果区加 live region**（读屏用户在 AI 追问与 known_hosts
导入这两条主流程上原本完全失明）。

### 1.4 显式留下的遗留项（**不是疏忽，是记录在案的边界**）

* `known_hosts_verify` 无「只有连接流程能写 ok」的闸门——它本就是**用户可见功能**
  （管理页里用户看着指纹点「信任」），且本应用的安全边界本就是「webview 即信任边界」。
  收紧的正解是**用户在场令牌**，已写进命令文档。
* 单标签主机名（`web01`）这类**无点内网名**不在主机名规则的 TLD 白名单内——
  白名单式设计的固有漏报，由「自定义规则」补。

## 2. 批次四：Ask Ottr 上下文入口（路线图 P0）

**目标**：此前 AI 只有两条入口——「命令失败自动诊断」与「右键解释选区」；想问点别的
（如「这台机器还剩多少内存？」）没有正规入口。

| 决定 | 落地形态 | 可裁定性 |
|---|---|---|
| 入口位置 | 终端工具行「问 Ottr」按钮 + 快捷键 **⌘⇧A**（⌘K 命令面板自动收录，registry 是键位单一来源） | 实现决定 |
| 呈现 | **复用右侧 AI 面板**（与诊断面板同一位置、同一状态机），首轮还没回答时底部输入条即提问框 | 实现决定 |
| 上下文 | 首轮带「最近输出尾（8KB）+ 主机备注」，但**不带**「退出码 + 失败命令」那段诊断语境——提问的语境是「刚发生了什么」 | 实现决定 |
| 追问 | 沿用既有多轮追问输入条 | — |

顺带修了两处由「追问轮」判据引入的问题（判据改为「带追问文本 **且** 已有对话历史」）：
Ask Ottr 的首轮不再被误判成追问轮（拿不到上下文）；诊断的「重试」不再把首轮上下文
**再追加一遍**。

## 3. 批次五：ssh-agent 桥接 + MCP 客户端 + AI 工具调用循环（路线图 P2）

### 3.1 系统 ssh-agent 桥接

| 决定 | 落地形态 |
|---|---|
| 凭据模型 | 新增凭据类型 **`agent`**：**不存任何密钥材料**，认证时 Ottr 只借用签名能力（私钥留在 agent 进程里） |
| 协议面 | 直接用 russh 自带的 agent 客户端（不自造协议实现）：unix 走 `$SSH_AUTH_SOCK`（或显式 UDS），windows 走命名管道 / Pageant |
| 认证面 | russh 的 `authenticate_publickey_with`（**外部签名器**）——服务端发来待签数据，转给 agent |
| 多身份 | agent 里通常有多把钥匙 → 逐个尝试，服务端拒掉某把就换下一把（与 `ssh` 一致） |

平台口径：**macOS/Linux 先做**（Windows 的命名管道 agent 需用户自行启动 OpenSSH agent；
两端都实现了，但页面与文案先按 unix 口径落地）。

### 3.2 MCP 客户端（Ottr 作客户端）

Ottr 此前只是 MCP **server**（给 Claude Desktop 等客户端用）。现在也能当**客户端**：
连接用户自己安装的外部 MCP server，列出并调用它们的工具。

| 决定 | 落地形态 |
|---|---|
| 传输 | **仅 stdio**（行分隔 JSON over 子进程 stdin/stdout）；HTTP/SSE transport 不在范围 |
| 协议常量 | **复用** server 侧的 `desktop/src/mcp.rs`（两份常量必然漂移） |
| 纪律 | 每请求 30s 超时、单行 1 MiB 上限（不无界缓冲）、子进程早退立即失败并带退出码 + stderr 尾、stderr 单独排空（否则管道写满挂住子进程） |
| 环境 | spawn 前 `env_clear()`，只给白名单项 + 用户配置的变量——**不把 Ottr 进程的环境（含任何机密）泄漏给外部子进程** |
| 存储 | 新表 `mcp_servers`；**env 变量的值不入表**，走 vault secrets（`mcp.env.<id>.<VAR>`，加密面） |
| 生命周期 | 一次性会话（起进程 → initialize → 干活 → 收进程），不常驻（常驻 = 外部进程生命周期不受控 + env 密钥长期驻留内存） |

UI 放在**设置 → MCP 分区**内的「外部 MCP 客户端」分区（不是插件面板：插件面板是
**应用内**插件的卡片视图，ADR 0002 明确排除外部插件执行，外部 server 的配置表单
不属于那里）。

### 3.3 AI 工具调用循环

模型可以发起工具调用并据结果续答。**安全模型沿用本应用既有约定：模型给建议、用户执行**
（诊断面板里的命令是「插入终端」不是自动跑）→ **MCP 工具调用同样必须用户点一下
「执行」**，模型不得自动触发工具。

| 决定 | 落地形态 |
|---|---|
| provider 面 | OpenAI 兼容：`tools` / `tool_calls` / `tool` 消息；Anthropic：`tools` / `tool_use` / `tool_result`。**端点不支持 tools 时降级为普通对话**（自动重发不带 tools 的一发，不报错——工具调用是增强项，不能反过来把 AI 功能搞挂） |
| 工具名 | `mcp__<server>__<tool>`（规范化；原始名靠运行期注册表还原） |
| 状态机 | 流结束有工具调用 → 助手轮入历史 → 挂待确认项 → **暂停**（`awaiting_tool_approval`）；用户执行/拒绝 → 结果作 tool 消息入历史 → 续跑一轮 |
| 轮次上限 | 5（超限后不带 tools 续跑，让模型据现有信息作答） |
| 脱敏 | 工具**返回文本**入库前脱敏；**工具参数不脱敏**（用户看到的即将执行的参数必须与实际调用一致） |

## 5. 已知限制（写在明处）

* MCP 客户端**只支持 stdio**；外部 server 需用户自己安装（Ottr 不内置任何 server）。
* MCP 客户端是一次性会话（每次调用重新起进程，`npx` 类 server 的冷启动成本每次都付）。
* AI 工具调用只覆盖 OpenAI 兼容与 Anthropic 两家协议面；兼容端点的工具调用碎片
  格式可能不规范（只认 `index`/`id`/`function.name`/`function.arguments`）。
* Windows 的 ssh-agent 需用户自行启动 OpenSSH agent（命名管道/Pageant 两条路都实现了）。
* IPv6 本机地址（`http://[::1]:…`）无法用 URLPattern 表达 → 本机端点用
  `localhost` / `127.0.0.1`。
* 工具名规范化有损（`foo.bar` → `foo_bar`）→ 原始名靠运行期注册表还原；server 被删
  或改名时回「工具不可用」给模型，不猜。
