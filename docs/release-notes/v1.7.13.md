## 🛠 1.7.13：连接不再卡死、导入不再半截、界面更跟手

一次覆盖全项目的性能与健壮性检查，重点修那些「平时不容易撞上、撞上就只能重启应用或重装」的毛病。

### 连接与传输不再卡死

- **远程终端敲字更跟手**：SSH 连接此前会攒着几个字节等对端确认才发出（网络协议里的一个常见策略），远程终端里每次击键都可能多等几十毫秒，敲起来发涩。现在这个策略被关闭，字符即时发出。
- **大文件传输不再被流控卡住**：单条连接的接收窗口偏小，传输大文件时容易被远端「等窗口调整」拖慢。现在窗口放大到 4 倍，高延迟链路上传输速度不再被这个上限压住。
- **远端服务器「不回话」时给出明确错误，而不是一直转圈**：远端进程僵死、或网络中间设备静默丢包时，列目录、打开文件、传大文件都会无限期等待。现在这些操作都有时限，到点直接报出「操作超时」，而不是界面一直空转。
- **FTP 之前最严重**：一次卡住后，这个连接上的所有后续操作（连关标签时的收尾也在内）都会排队等下去，只能重启应用才能恢复。现在同样有了时限，卡住不再拖垮整条连接。
- **FTP 连接新增存活探测**：以前 FTP 会话完全没有断线感知，服务器断开后标签仍显示「已连接」，直到你真的去操作才发现问题、且无从判断是哪一步断的。现在会定期探测，断开后自动进入重连流程。

### 出错时能自己恢复

- **终端连接意外中断会正常收尾**：此前这类意外会让标签一直显示「已连接」、录制文件不落库、后台任务空转。现在会关闭连接、通知界面、把录制正常落库。
- **远端文件通道损坏后能自愈**：远端文件子系统一旦出问题，之前必须断开重连才能恢复；现在会自动重建通道并重试。

### 批量导入主机更稳

- **导入不会留下「一半」**：导入 CSV、SSH 配置、Tabby、Xshell 时，此前中途失败会留下导入了一半的主机列表，而且看不到到底导入了多少、哪一行出的问题。现在整批要么全部成功、要么一行都不落库，失败原因逐条列在报告里。

### 界面更跟手

- **拖动侧栏宽度更顺滑**：拖拽期间不再反复重绘整个窗口。
- **传输进度不再让文件面板卡顿**：进度更新原本每 0.1 秒就会重绘一次整个面板，几千个条目的目录下这一项很明显地拖慢操作。现在进度不再触发整面板重绘。
- **打开应用更快**：启动时的事件接线由串行改为并发，首屏少等几次往返。
- **AI 回答里的 Markdown 改为按需加载**：首屏体积减少约 156 KB；并补上了「内容异步到达后对话流自动贴底」，避免新回答落在屏幕折线以下、让人以为没反应。
- **几千个文件的大目录依然滚得动**：目录滚动与键盘定位保持流畅。

## 验证情况

- 自动化测试：前端全量 176 个测试文件、2146 个用例；Rust 侧工作区全部用例。类型检查无错，静态检查零告警。
- **真实 Linux 设备走查（192.168.9.102，WebKitGTK）**：SSH 连接建立并通过首次连接的指纹确认；远程终端里**实际敲命令**并得到正确回显；远端目录 2423 项的滚动与键盘定位；50 MB 文件下载后校验值与源文件完全一致；FTP 全流程（上传、下载、续传、取消后重传、身份校验）全部通过；「服务端不回话」时 30 秒内给出明确错误而非挂死。
- 未覆盖（逐条说明原因）：FTP 在传输中途断流的空闲超时未在真实设备上验证（与已验证的控制面超时是同一套机制）；macOS 与 Windows 的具体界面行为由 CI 的三平台构建覆盖，未做逐项走查。
- 本版本不含数据库迁移，无需手动升级操作。

## 📦 平台提示

- macOS：本版本未使用 Apple 开发者签名。首次打开如提示「已损坏，无法打开」，在终端执行 `xattr -cr /Applications/Ottr.app`；
  连接局域网主机如提示 No route to host 或要求本地网络授权，见 README「macOS 提示已损坏或连不上局域网主机」一节。
- Windows：安装时如遇 SmartScreen 拦截，点「更多信息 → 仍要运行」。便携版
  （zip 解压即用）不提供应用内自动更新，升级请下载新版 zip 解压覆盖。
- Linux：AppImage 需 `chmod +x` 后运行；deb/rpm 按发行版安装。
