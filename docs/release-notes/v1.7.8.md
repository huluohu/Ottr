## 🛠 1.7.8：通知中心显示修复 + 加载健壮性

在 Linux 真机上逐个界面走查后修掉的问题，外加把其中几类容易复发的毛病加进自动检查。

### 体验类

- **通知中心没有通知时，提示一直贴在面板顶部**：下面的区域大片留白，看起来像界面没加载完。原因是给这个提示块写的样式**从未生效**——代码里那个元素只挂了给自动化测试用的标记，没挂对应的类名，浏览器根本没匹配到这条规则。补上之后提示块才真正垂直居中。
- **投递失败的那一行掉在通知卡片外面**：通知条目被画成一张张卡片，但卡片外观挂在了条目按钮上，而「投递失败」行是它在同一个列表项里的**兄弟节点**——失败行于是掉到卡片框外，看起来像「第二张卡片粘在条目下面」。同一行的「重发」按钮还带着自己的底色边框、字号比所在行大一号，会向上溢出压进卡片。现在卡片由整个列表项承担，失败行落在卡片内，「重发」改成轻量文字按钮（鼠标移上去才显形）。
- **某一张表的数据有异常时，整个应用看起来被清空**：启动时界面并行读取主机、凭据、分组、跳板链四张表，此前只要其中任意一张读取失败，整个读取批次就一起失败、四张表的结果全不落地——用户看到的是主机列表空、凭据空、分组空加一条红色报错，像是数据被清空。真正的故障点往往只是其中一张表的一行。现在逐张表独立处理：读成功的表照常显示，读失败的表保留上一次的内容，错误信息汇总后继续提示。失败仍会照常上报，不会被静默吞掉。

### 自动化检查

- 自动布局检查新增三条：通知中心、定时任务、端口转发、跳板链这四个面板必须**横向占满**整个内容区（此前只查高度，而「卡片被压成窄条」是横向问题，高度检查不会报警）；没有数据时的提示必须在其面板内**垂直居中**；某条样式在代码里对应的元素在页面上完全找不到时（说明这条样式从未生效过），直接报出来。每条都来回验证了两遍——把已发布过的坏版本换回去，确认检查精确变红且报错与实际缺陷一一对应，再还原确认重新变绿。

- 真机验证（Ubuntu 24.04）：逐界面截图复核——投递失败行确实落在通知卡片内、「重发」按钮不再溢出、没有数据时的提示确实垂直居中（偏离 18px，此前为 219px）、四个面板均占满内容区（内容区宽 931px、面板两侧各留 53px）；并在库里留一行异常数据的条件下确认主机列表仍正常显示。

## 📦 平台提示

- macOS：本版本未使用 Apple 开发者签名。首次打开如提示「已损坏，无法打开」，在终端执行 `xattr -cr /Applications/Ottr.app`；
  连接局域网主机如提示 No route to host 或要求本地网络授权，见 README「macOS 提示已损坏或连不上局域网主机」一节。
- Windows：安装时如遇 SmartScreen 拦截，点「更多信息 → 仍要运行」。便携版
  （zip 解压即用）不提供应用内自动更新，升级请下载新版 zip 解压覆盖。
- Linux：AppImage 需 `chmod +x` 后运行；deb/rpm 按发行版安装。
