## 🛠 1.7.7：全库体检后的修复集

一次全库扫描（四个方向并行：Rust 核心库 / 加密与持久化 / 命令层运行链 / 前端残余面）后修掉的问题。每条都经独立复核确认。

### 崩溃类

- **长命令输出超限时可能整个应用崩掉**：记录「命令输出已截断」时按**字节**切命令文字，第 80 字节落在中文/emoji 等多字节字符中间就会触发崩溃，而发布版遇崩溃即终止——等于整个应用被杀掉。触发条件：命令超过 80 字节、边界落在多字节字符中间，且该命令输出超过 10MB（批量执行、AI、定时任务都会走到）。改为按字符截断。

### 数据类

- **删除的录制文件，其终端全文永久残留在库里**：一次历史迁移重建录制表时连带删掉了全文索引的删除触发器且未重建。此后无论显式删除录制还是删主机，索引里都会留下一行「幽灵」——**已删除录制的终端全文（纯明文）永久留在库文件里**，删除语义失效、索引无限膨胀。更隐蔽的是：检索语句是索引 JOIN 录制表，幽灵行对检索不可见，所以既有的测试一直是全绿、钉不住这个问题。
  **本次新增一次数据库迁移**：重建触发器 + 一次性清掉历史欠下的孤儿行。升级既有库与全新安装都会自动完成，无需手动操作。
- **退出应用时正在录制的视频会变成删不掉的孤儿**：所有退出路径都是直接结束进程，录制收尾任务来不及跑，正在录的文件不会入库，成为「界面看不见、删除功能找不到、也没有任何清扫路径」的孤儿。现在退出时统一收尾；此外新增兜底——强杀或断电漏网的孤儿文件会在下次启动自动归档入库（只归档不删除，60 秒安全窗避免误伤正在录的文件）。

### 安全类

- **首装时可以设成一位数字的主密码**：「首次解锁即设置主密码」这条路径（Linux 无系统钥匙串时的首次安装走这里）此前不校验最小长度——一位数字甚至空密码都能设成主密码并落盘。仓库约定明确要求「绕过前端直连接口也必须被后端拦住」，现在两条设密路径共用同一道校验。**存量库不受影响**：已有主密码的库按原样解锁，不会因历史遗留的短密码被挡在门外。
- **两个标签同时首次连接陌生主机，第一条问询会凭空消失**：主机密钥确认框只有一个槽位，第二个问询到来会直接把第一个顶掉（既不代为处理也不排队）。结果是第一个标签的确认界面永久消失，那个会话一直卡到后端 60 秒超时被静默拒绝——指纹变更告警的情况下用户甚至看不到任何告警就被自动拒了。现在改成排队：一次只弹一个，处理完自动出下一个；关标签时队头自动接上。

### 体验类

- **主机密钥确认超时后，弹窗永远关不掉**：60 秒不回答就按拒绝处理，但此前超时既不通知界面也不回收问询——弹窗一直开着，用户点「信任并连接」会写下一条信任记录然后毫无反应，标签停在「未连接」，用户还不知道连接到底是超时还是被拒。现在超时会对齐交互式认证问询的既有做法：收回问询、关掉弹窗、记下真实原因。
- **解锁/升级密码时界面会卡住**：解锁、升级到主密码、降级回钥匙串这三个操作在界面主线程上跑 Argon2 派生或全库重新密封，期间窗口无法拖动、菜单点不动。改为后台线程执行。
- **主密码过短的报错直接显示英文**：上面那条修复在真机验证时暴露的连带问题——当「首次解锁」的状态信号缺失时，前端长度预检不命中，后端英文原文直接上屏。现在两种路径都显示本地化文案。

## 验证情况

- Rust crates 测试、桌面端单元测试、前端全量测试、格式与静态检查、13 个界面的自动布局检查全部通过；新增测试用例覆盖上述各条。
- 真机验证（Ubuntu 24.04）：数据库迁移在「已被旧迁移破坏的库」上验证（触发器重建、幽灵数据清零、删除语义恢复）；一位数字主密码被拒且未落盘；主机密钥弹窗 60 秒后自动收起；强杀留下的录制文件在下次启动自动入库。
- 未覆盖：Windows 平台的对应行为；多字节字符触发的那条崩溃路径（验证环境缺少多字节输入条件）；两个标签并发连接的场景（模态弹窗期间无法构造）。

## 📦 平台提示

- macOS：本版本未使用 Apple 开发者签名。首次打开如提示「已损坏，无法打开」，在终端执行 `xattr -cr /Applications/Ottr.app`；
  连接局域网主机如提示 No route to host 或要求本地网络授权，见 README「macOS 提示已损坏或连不上局域网主机」一节。
- Windows：安装时如遇 SmartScreen 拦截，点「更多信息 → 仍要运行」；便携版
  （zip 解压即用）不提供应用内自动更新，升级请下载新版 zip 解压覆盖。
- Linux：AppImage 需 `chmod +x` 后运行；deb/rpm 按发行版安装。
