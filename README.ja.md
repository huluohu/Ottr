**Ottr** は軽量なオープンソース AI SSH クライアントです。インストール後のサイズは約 8 MB（AppImage 版は 84 MB）、常駐メモリは約 100 MB で、バックグラウンドサービスも、別途導入が必要なエージェントもありません。「サーバーに接続してコマンドを入力する」という作業を「ターミナルが AI を理解する」に変えました。失敗したコマンドの原因を診断し、自然言語からコマンドを生成し、履歴はどの場所からでも検索できます。

Ottr が決して破らない大前提はひとつだけです。**AI キーはご自身でお持ちください（BYOK）**。リクエストはお使いの端末から、選択したモデルエンドポイントへ直接送られます。間に Ottr のサーバーを介在させることはありません。秘密情報はお使いの端末上で暗号化して保存し、ホスト情報とコマンド履歴はローカルの SQLite ファイルに保持します。AI リクエストとオプションの同期について、具体的なデータ境界は [プライバシーと AI](#-privacy--ai-data-boundaries) で説明しています。

## ✨ できること

### ターミナルとセッション

- **タブと分割ペイン**（左右または上下に分割）、GPU アクセラレーションによる描画、検索、URL 検出、完璧なエスケープシーケンス対応
- **自動判別するエンコーディング**: UTF-8 / GBK / GB18030 を自動で検出し、手動での切り替えも可能——中国語版の Windows サーバーでは特に重要です
- **自己修復する接続**: バックオフ付きの自動再接続、keepalive による切断リンクの検出、接続状態のインジケーター、再起動後のタブ復元
- **セッション録画**を [asciinema v2](https://docs.asciinema.org/manual/asciinema-v2/) 形式で保存でき、アプリ内のタイムラインプレイヤー（シーク、速度変更）にも対応。共有可能な **秘匿情報をマスクしたテキスト** として書き出せます

### ホストと認証情報

- グループ、タグ、検索、そして **⌘K によるあいまい検索のクイックコネクト**。インポートとエクスポートは `~/.ssh/config`、Tabby（JSON/YAML）、Xshell のセッション、CSV に対応しています。エクスポートに含まれるのはホスト情報のみで、秘密情報が混ざることはありません
- 認証情報保管庫: パスワード、SSH キー（ed25519/ecdsa/rsa——生成、インポート、公開鍵の配置）、TOTP による二次認証をホストに紐づけられ、**名前を付けられる**ため、1 つの認証情報を複数のホストで使い回せます
- **ジャンプホストのチェーン**を視覚的に構成でき、**ポートフォワーディング**（ローカル、動的 SOCKS、リモート）にも対応。切断後も自動的に再確立されます
- known_hosts は **trust-on-first-use に加えて定期的なフィンガープリント監査** を行い、man-in-the-middle 攻撃を検知します

![ダークテーマ：アイコンレール、ホストパネル、浮遊するタブ群、接続状態のドット表示](docs/screenshots/main-dark.png)

### データを尊重する AI

- **失敗時に診断**: 終了コードが 0 以外になると、推定される原因と修正案を表示します。確認なしに実行されることはなく、危険なコマンドは赤く警告されます
- **⌘J でコマンドを生成**: 日本語または英語で望みたいことを記述すると、現在のディレクトリを基準とした 1 行のコマンドが返ってきます
- **選択して解説**: 選択したテキストを右クリックして、解説・翻訳・修正ができます。セッション終了時には自動生成のサマリーを添えられ、⌘R で検索できます
- **BYOK をさまざまなプロバイダーで**: OpenAI 互換エンドポイント（**OpenAI / DeepSeek / Zhipu GLM / 自分でホストする任意のエンドポイント**）、Anthropic Claude、ローカルの Ollama に対応。プリセットを選ぶとエンドポイントまで自動で入力され、キーはお使いの端末上で暗号化されます
- **ルールによる秘匿情報のマスク**: 診断・解説・サマリー内で一致した内容はプレースホルダーに置換されます。ただしすべての秘密情報を確実に捕捉できるとは限りません。自然言語でのコマンド入力と現在のディレクトリのコンテキストは **マスクされません**。Ottr には MCP サーバーも同梱されており（3 つのプラットフォームすべて）、Claude Desktop や Cursor などの任意の stdio MCP クライアントと通信できます。ホストごとの認可と呼び出しごとの承認に対応しています

### 監視・アラート・運用

- **エージェント不要の監視**: CPU / メモリ / ディスク / ロード / ネットワークのライブチャートとプロセスブラウザを備え、複数ホストをまとめて確認できます
- **アラートルール**（ディスク、CPU、プロセス、ログキーワード）を **12 種類の通知チャネル** へ振り分けます。WeCom、DingTalk、Feishu、Telegram、Slack、Discord、SMTP メールなどに対応し、レート制限、リトライ、配信履歴の永続化も行います
- **定期タスク**はネイティブなスケジューラで実行されます（実行し損ねた履歴も記録され、消失しません）。加えて、選択したホストに対する **一括実行** が、スニペットライブラリ、並列数、タイムアウトの制御付きで利用できます

### ファイルと同期

- **2 ペインの SFTP ブラウザ**: ドラッグ＆ドロップ転送、並列チャンク、再開可能なアップロードに対応。trzsz（trz/tsz）にも対応し、FTP と FTPS も同じように利用できます
- **リモート編集**をお使いのローカルエディターで行えます。保存はアトミックなので（失敗してもリモートファイルが壊れることはありません）、バイナリ判定により誤編集も防げます
- **複数デバイス間の同期**は、エンドツーエンド暗号化のエンベロープ（AES-256-GCM + PBKDF2）を通じて、**WebDAV、Git、またはローカルフォルダ** の 3 つのチャネルのいずれかで実現します（WebDAV はネイティブプロキシ経由で自前のドライブへ直接接続するため、クロスオリジン制限はありません）。カテゴリ単位の push / pull に対応し、競合は 1 件ずつ手動で判断できます

### 検証できるセキュリティ

- 秘密情報と認証情報は **AES-256-GCM** で保護されています（データベース全体の暗号化ではありません）。モードは 2 種類で、既定は **キーチェーンモード**（マスターキーがシステムのキーチェーンに保管されるため、アプリを起動するだけです）、あるいは **マスターパスワードモード**（Argon2id による鍵導出——パスワードがなければ秘密フィールドを復号できません）。いつでも切り替えられ、切り替えるたびに秘密情報は再暗号化されます
- 機密情報の複製はスケジュールに従って自動的に消去され、ロック画面には「パスワードを忘れた場合」のガイド付きリセットが用意されています（確認あり。クラウドバックアップには影響しません）
- Ottr は **テレメトリを送信しません**。ただし AI 機能と同期機能は、動作に必要なデータを送信します——それは「ホスト情報がお使いの端末から出ることはない」という意味ではありません

## 📦 ダウンロードとインストール <a id="-download--install"></a>

[**Releases**](https://github.com/huluohu/Ottr/releases) からお使いのプラットフォーム向けのビルドを入手してください:

| プラットフォーム | 形式 |
|---|---|
| macOS（Apple Silicon） | `.dmg` |
| macOS（Intel） | `.dmg` |
| Windows | `.msi` / `.exe` インストーラー、または **`_x64_portable.zip`（インストール不要）** |
| Linux | `.deb` / `.rpm` / `.AppImage` |

初回起動時に、このマシンで秘密フィールドをどう暗号化するか（データベース全体ではなく）を Ottr が尋ねます。**キーチェーンモード**（パスワードを覚える必要がありません）か **マスターパスワードモード**（これがないと秘密フィールドを復号できません）のどちらかです。

**Windows ポータブルビルド**: 任意の位置で展開して `Ottr.exe` を実行してください。インストールは不要で、設定とデータはアプリと同じ場所にある `Ottr/data/` に保存されます（このフォルダをコピーすれば環境を移せます。削除すればアンインストールになります。WebView2 が必要ですが、通常は Win10/11 に同梱されています）。ポータブルビルドは自動更新に対応していないため、新しい zip をダウンロードして古い zip を上書きしてください。`data/` を残せば設定はそのまま引き継がれます。

インストール版には **アプリ内更新** があります（設定 → このアプリについて。署名済みのパッケージのみ対象）。手動のダウンロードは、いつでもこのページから行えます。

<details>
<summary><strong>🍎 macOS が「破損している」と表示する場合、または LAN に接続できない場合の対処</strong></summary>

Ottr はまだ Apple Developer ID で署名されていないため、macOS が通常より厳しく判定します——**ダウンロードが破損しているわけではありません**。2 つのステップで解決します。

**1️⃣ 「Ottr は破損しているため開けません。ゴミ箱に移してください」**

ターミナルを開いて次を 1 回実行し、その後に Ottr を通常どおり起動してください（更新のたびに繰り返してください）:

```bash
xattr -cr /Applications/Ottr.app
```

**2️⃣ LAN 内のマシンに接続するときに「No route to host」と表示される**

macOS 15 以降、アプリはネットワーク上のデバイスへアクセスするために「ローカルネットワーク」へのアクセス許可を与えられる必要があります。プロンプトが表示された場合は **許可** をクリックしてください。一度も表示されないまま接続が失敗する場合は、次のいずれかを選んでください:

- **ターミナルから Ottr を起動する**（この方法で起動したアプリには影響しません）:

  ```bash
  /Applications/Ottr.app/Contents/MacOS/ottr &
  ```

- **LAN のアドレス範囲を一度だけ許可する**（管理者パスワードの入力を求められます。`192.168.9.0/24` をお使いのアドレス範囲に置き換えてから、再起動してください）:

  ```bash
  sudo defaults write com.apple.network.local-network AllowedWiFiLocalNetworkAddresses -array "192.168.9.0/24"
  sudo defaults write com.apple.network.local-network AllowedEthernetLocalNetworkAddresses -array "192.168.9.0/24"
  ```

  後でシステム既定値に戻すには、次のコマンドを実行して、もう一度再起動してください:

  ```bash
  sudo defaults delete com.apple.network.local-network AllowedWiFiLocalNetworkAddresses
  sudo defaults delete com.apple.network.local-network AllowedEthernetLocalNetworkAddresses
  ```

Ottr が正式な Apple Developer ID で署名されるようになれば、この手順は一切不要になります。

</details>

## 🚀 クイックスタート

1. **ホストを追加**: サイドバーの「新しいホスト」（グループ名にホバーして **＋** を押すと、そのグループに直接追加できます）または「ssh config をインポート」から追加します。ホストの行をダブルクリックすると接続します——初回接続時にフィンガープリントが表示され、許可した後は確認されなくなります
2. **AI を有効化**: 設定 → AI → プロバイダーを追加します（Zhipu GLM、DeepSeek、Ollama などのプリセットを選び、キーを貼り付けます）。これで失敗したコマンドは自動的に診断され、**⌘J** で自然な言語の要望をコマンドに変換できます
3. **アラートを設定**: 設定 → アラート → 通知チャネルを追加します（テストメッセージを送信して動作を確認）→ 「root パーティション > 90%」のようなルールを作成します。同じページの「通知タイプ」セクションで、どのイベントを通知するかを指定できます
4. **デバイス間で同期**: 2 台目のデバイスに Ottr をインストールし、設定 → 同期 でチャネルを選択します（WebDAV の場合はドライブの URL を入力します）。同期用のパスフレーズを設定したら **今すぐ同期** を押してください
5. **さらに活用**: **⌘R** で履歴を検索、**⌘D**（Windows/Linux では Ctrl+⇧D）でペインを分割。「ファイル」メニュー（macOS）でホストをインポート／エクスポート、「ツール」メニュー（macOS）または **⌘K** パレットから、ポートフォワーディング、ジャンプホストのチェーン、定期タスク、一括実行、通知センターへアクセスできます（未読数はアイコンレールと各メニューに表示されます）

## 🔐 プライバシーと AI のデータ境界 <a id="-privacy--ai-data-boundaries"></a>

- **ローカル保存**: SSH パスワード、秘密鍵、キーのパスフレーズ、AI API キーは AES-256-GCM でフィールドごとに暗号化されます。一方、ホストアドレス、ユーザー名、メモ、コマンド履歴、通常の設定はローカルの SQLite ファイルに平文のまま残ります——保管庫をロックしたりマスターパスワードを設定したりしても、これらは暗号化されません。同期は独自の暗号化エンベロープを使用し、ローカルデータベースの保存方法には影響しません
- **診断と解説**: 診断では、失敗したコマンドとターミナル出力の末尾（最大 8 KB）が送信されます。解説では、選択したテキストが送信されます。送信前に、ルールによって IP アドレス、パスワードの代入、メールアドレス、条件によってホスト名と利用者が定義したパターンが置換されます。要約にも同様のルールがコマンド列に適用されます。サンプル、内部名、業務データと見かけない秘密情報は見落とす可能性があります。「N 件を秘匿化」の件数は一致数であり、完全に捕捉できたことを保証するものではありません。パネルにはローカルで元のテキストが表示される場合があります
- **自然言語からのコマンド生成**: ご要望と現在のディレクトリ（OSC 7）が、コンテキストとして選択したモデルエンドポイントへ、上記の秘匿化処理なしに送信されます。パスワード、トークン、送信されたくない内容は入力しないでください。直接接続していても、プロバイダーが内容を受信または保持することを止めることはできません——それはプロバイダーの対応によります
- **Ollama**: プリセットのエンドポイントは `http://localhost:11434/v1` です。処理がローカルに留まるのは、エンドポイントと推論の双方がこのマシン上にある場合のみです。リモートアドレス、プロキシ、クラウドモデルに変更した場合、コンテンツがローカルのまま保持在保証できません
- **AI コマンドの挿入**: 改行や制御文字を含まない 1 行のテキストのみ受け付けられ、末尾にキャリッジリターンが追加されることもありません。複数行の内容はそのまま保持され、挿入は無効になります——内容を確認して、ご自身でコマンドを用意してください。連結や 1 行目への切り詰めは行われません。危険度表示はヒントであり、コマンドが安全であることの証明ではありません。挿入前に、ターミナルが想定どおりの状態かを必ず確認し、入力済みの内容も確認してください。カスタムキーバインドや対話型プログラムは、この保証の対象外です
