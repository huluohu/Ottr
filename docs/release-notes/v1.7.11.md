## 🛠 1.7.11：对话流可读性与输入可用性

修「问 Ottr / 命令诊断」面板里两个用户实报的问题：对话里分不清谁在说话；AI 答完以后输入框不能打字。

### 体验类

- **工具调用和你的提问长得一模一样**：对话流里此前只有两类样式——你的提问是填充气泡，AI 的回答是纯文本；而**工具调用气泡也用了填充气泡**（和你的提问同一套样式），所以「调用主机工具 ottr_exec_command」读起来像是「你说了这句话」。现在三类角色各有各的样子：**你的提问 = 填充气泡**（不变）、**AI 的回答 = 纯文本正文**（不变）、**工具调用 = 虚线小签**（透明底 + 虚线边框 + 小字，系统动作而非人说话）。
- **AI 答完以后输入框不能打字，且没有原因**：输入被禁用的真实原因是「上面还有待你确认的命令或工具调用」——按设计这时输入框要禁用（不然会打断你处置的流程）。问题出在两处：禁用**一个字都不说**，只灰着；而且要处置的那张卡**可能已被对话流顶出可视区**（你的画面上右下角正浮着「回到最新」按钮，说明视口不在底部），那张卡你根本没看见。现在输入框上方会写明原因，并给一个**「带我去处置」**按钮——点一下就把待确认的卡滚进可视区。

## 验证情况

- 自动化测试：前端全量 176 个测试文件、2139 个用例全部通过（本次新增 3 条：角色样式不重样 / 禁用原因可见 / 无待处置项时不显示多余提示）。
- 自动布局检查新增「工具调用与用户提问不得同款」断言：把气泡改回同款 → 三轮精确变红；还原后 22/22 视图通过。类型检查无错。
- **真机验证（Ubuntu 24.04，WebKitGTK）**：三类角色的样式差异已在真机截图上确认（工具调用是虚线签、提问是填充气泡、AI 回答是纯文本）；AI 答完一轮后**实际敲入并发送了第二个问题**，输入框可正常继续追问。
- 未覆盖：**「有待确认的命令」时输入禁用 + 原因提示 + 「带我去处置」这条路径的真机实测**——它要求远端主机且逐条确认档（本地会话的执行类命令被后端直接拒，不会挂成待确认卡）；真机上接远端主机受阻于两件事：主机树的双击在 WebKitGTK 上无法用合成鼠标事件触发，以及设备的容器镜像源与 GitHub 下载被挡、sshd 夹具无法重建。该路径目前由单元测试与无头浏览器的布局检查覆盖（含来回验证）。另：**macOS 上的目视确认**、**Windows** 平台行为未覆盖。本版本不含数据库迁移，无需手动升级操作。

## 📦 平台提示

- macOS：本版本未使用 Apple 开发者签名。首次打开如提示「已损坏，无法打开」，在终端执行 `xattr -cr /Applications/Ottr.app`；
  连接局域网主机如提示 No route to host 或要求本地网络授权，见 README「macOS 提示已损坏或连不上局域网主机」一节。
- Windows：安装时如遇 SmartScreen 拦截，点「更多信息 → 仍要运行」。便携版
  （zip 解压即用）不提供应用内自动更新，升级请下载新版 zip 解压覆盖。
- Linux：AppImage 需 `chmod +x` 后运行；deb/rpm 按发行版安装。
