## 🚀 1.6.3：修复 v1.6.2 升级后主机凭据绑定丢失的缺陷

> **如果你在 1.6.2 上遇到「所有主机都连不上 / 提示未绑定凭据」，请更新到本版本。**
> 1.6.3 会自动把被清空的凭据绑定找回来，并把仍需手动处理的主机列给你。

### 这次修了什么

- **升级后主机连不上的根因**：1.6.2 在升级时重建内部凭据表，数据库的「引用完整性」机制被触发，把所有主机与凭据的绑定关系静默清空（升级即断连）。
  - 修复：升级过程中不再让数据库执行这类隐式改写——今后升级不会再有主机掉绑定。
- **已中招的自动恢复**：升级到 1.6.3 时，Ottr 会按「主机名 ↔ 凭据名」把绑定自动接回去（例：`办公Ubuntu` ↔ `办公电脑`、`9.58` ↔ `58`、`NAS-local` ↔ `NAS`）。
  - 接回后随时可在主机编辑界面改绑或解绑。
- **没接上的会明确告诉你**：无法唯一判断的主机不会被瞎猜着绑定（绑错会导致认证失败，误导排查方向），而是在启动时**点名列出**让你手动指定凭据。
- **顺带修**：设置页「检查更新」按钮在失败提示很长时被挤成两行文字的变形问题；更新检查失败时不再把底层网络报错原文（含内部地址）直接显示在界面上，改为一句能据以行动的说明，并自动重试一次。

### 升级建议

- 如果你在 **1.6.0** 上且一切正常：可以直接升到 1.6.3，中间没有需要手动处理的步骤。
- 如果你已经在 **1.6.2** 上且主机连不上：升到 1.6.3 后重新打开应用即可（自动恢复在应用启动时进行）；仍连不上的主机按启动提示手动绑定一次凭据即可。
- 若你的凭据来自系统 ssh-agent，请确认 agent 仍在运行（新增的系统 ssh-agent 凭据类型在 1.6.2 起可用）。

## 📦 平台提示

- macOS：本版本未使用 Apple 开发者签名。首次打开如提示「已损坏，无法打开」，在终端执行 `xattr -cr /Applications/Ottr.app`；
  连接局域网主机如提示 No route to host 或要求本地网络授权，见 README「macOS 提示已损坏或连不上局域网主机」一节。
- Windows：安装时如遇 SmartScreen 拦截，点「更多信息 → 仍要运行」；便携版
  （zip 解压即用）不提供应用内自动更新，升级请下载新版 zip 解压覆盖。
- Linux：AppImage 需 `chmod +x` 后运行；deb/rpm 按发行版安装。
