## 🛠 1.7.8：通知中心显示修复 + 加载健壮性

在 Linux 真机上逐个界面走查后修掉的问题，外加把其中几类回归钉进自动化检查。

### 体验类

- **通知中心没有通知时，空状态一直贴在面板顶部**：下面的区域大片留白，看起来像界面没加载完。原因是给这个引导块写的样式**从未生效**——元素在代码里只挂了测试用的标记，没挂对应的类名，浏览器根本没匹配到那条规则。补上之后引导块才真正垂直居中。
- **投递失败的那一行掉在通知卡片外面**：通知条目被画成一张张卡片，但卡片外观挂在了条目按钮上，而「投递失败」行是它在同一个列表项里的**兄弟节点**——失败行于是掉到卡片框外，看起来像「第二张卡片粘在条目下面」。同一行的「重发」按钮还带着自己的底色边框、字号比所在行大一号，会向上溢出压进卡片。现在卡片由列表项承担，失败行落在卡片内，「重发」改成轻量文字按钮（悬停才显形）。
- **某一张表的数据有异常时，整个应用看起来被清空**：启动时界面并行读取主机、凭据、分组、跳板链四张表，此前只要其中任意一张读取失败，整个读取批次就一起失败、四张表的结果全不落地——用户看到的是主机列表空、凭据空、分组空加一条红色报错，像是数据被清空。真正的故障点往往只是其中一张表的一行。现在逐张表独立处理：读成功的表照常显示，读失败的表保留上一次的内容，错误信息汇总后继续提示。失败仍会照常上报，不会被静默吞掉。

### 工程保障

- 自动布局检查新增三条断言：库级视图必须**横向铺满**主区（此前只查高度，而「卡片被压成窄条」是横向问题，高度检查不会报警）；空状态必须在其面板内**垂直居中**；某条样式规则对应的元素在页面里完全不存在时（说明这条样式从未生效）直接报出。每条断言都做了双向验证——把已发布过的坏版本换回去，确认检查精确变红且报错与实际缺陷一一对应。

## 验证情况

- 自动化测试：前端全量 176 个测试文件、2122 个用例全部通过（含本次新增 3 条数据加载回归用例）；19 个界面的布局检查全部通过，其中新增三条断言均经「注入坏版本 → 精确变红 → 还原 → 恢复全绿」验证。
- 真机验证（Ubuntu 24.04）：逐界面截图复核——投递失败行确实落在通知卡片内、「重发」按钮不再溢出、空状态确实垂直居中（偏离 18px，此前为 219px）、四个库级视图均铺满主区（主区 931px、面板两侧各 53px 内边距）；并在库中留一行异常数据的条件下确认主机列表仍正常显示。
- 未覆盖：**macOS 上的目视确认**（本轮验证在 Linux 真机上完成，未占用 macOS 桌面环境）；**Windows** 平台行为。本版本不含数据库迁移，无需手动升级操作。

## 📦 平台提示

- macOS：本版本未使用 Apple 开发者签名。首次打开如提示「已损坏，无法打开」，在终端执行 `xattr -cr /Applications/Ottr.app`；
  连接局域网主机如提示 No route to host 或要求本地网络授权，见 README「macOS 提示已损坏或连不上局域网主机」一节。
- Windows：安装时如遇 SmartScreen 拦截，点「更多信息 → 仍要运行」。便携版
  （zip 解压即用）不提供应用内自动更新，升级请下载新版 zip 解压覆盖。
- Linux：AppImage 需 `chmod +x` 后运行；deb/rpm 按发行版安装。
