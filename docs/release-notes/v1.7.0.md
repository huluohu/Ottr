## 🚀 1.7.0：「问 Ottr」执行模式（第一阶段）——能动手，但默认只出计划

- **「问 Ottr」现在能对主机动手了**，并新增三档执行模式：**Plan / Auto / Manual**，在问答面板顶部随时切换。
  - **Plan（默认）**：AI 可以读取当前终端输出、读取主机文件、列出目录、查看进程；**任何要执行命令的请求都只写进「计划」，一条都不会真跑**。计划以清单形式列出：命令原文、危险等级（安全 / 需过目 / 危险）、当前状态。
  - **Manual / Auto**：本阶段尚未开放（选到这两档会明确说明），后续分阶段交付——Manual 是逐条确认后执行，Auto 是白名单内自动执行、其余降级确认。
- **多主机严格隔离**：每个终端对话独立保存上下文、对话与计划；A 终端的提问、回答与命令绝不串到 B 终端；同主机多开、同一页签分屏、重连换连接都各自独立。
- **AI 只读探查开关**（设置 → AI）：可一键关掉「读取主机文件与目录」，关闭后 AI 只能看终端输出，看不到主机文件；该设置只保存在本机，不随同步走。
- **新对话默认执行模式**（设置 → AI）：默认 Plan。

### 关于安全边界

- 本阶段**任何命令都不会被自动执行**；要让 AI 真的动手，需要切到 Manual/Auto 并逐条确认（后续阶段）。
- 本机（本地终端）的文件读取**不开放给 AI**：避免你的 SSH 私钥、云凭据、kube 配置等内容被发送到模型服务。
- 远端主机的只读范围限定为**登录账号的家目录**；系统路径（如 `/var/log`、服务配置）要放开，留到后续的按主机授权阶段。
- 外部 MCP 服务的工具始终需要你逐次确认——它们在服务端自行决定连接哪台机器，Ottr 无法核验。

## 📦 平台提示

- macOS：本版本未使用 Apple 开发者签名。首次打开如提示「已损坏，无法打开」，在终端执行 `xattr -cr /Applications/Ottr.app`；
  连接局域网主机如提示 No route to host 或要求本地网络授权，见 README「macOS 提示已损坏或连不上局域网主机」一节。
- Windows：安装时如遇 SmartScreen 拦截，点「更多信息 → 仍要运行」；便携版
  （zip 解压即用）不提供应用内自动更新，升级请下载新版 zip 解压覆盖。
- Linux：AppImage 需 `chmod +x` 后运行；deb/rpm 按发行版安装。
